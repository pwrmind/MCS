# MCS v3.0 — Визуальный конструктор архитектуры микросервисов

**MCS (Microservices Connection Specification)** — интерактивный веб-редактор для визуального проектирования и редактирования архитектуры микросервисных систем.

Проект представляет собой **Single Page Application** на чистом HTML/CSS/JavaScript (без фреймворков и сборки), которая позволяет моделировать сервисы, их эндпоинты и связи между ними с живым JSON-представлением.

## Возможности

- **Визуальный канвас** — SVG-диаграмма сервисов и связей между ними
- **Drag & Drop** — перемещение сервисов по холсту, создание связей перетаскиванием от коннектора к коннектору
- **Палитра узлов** — создание сервисов, REST/gRPC/Kafka эндпоинтов, связей
- **Инспектор параметров** — редактирование всех свойств выбранного элемента (таймауты, retry policy, контракты, режимы strict/override)
- **Live JSON** — правая панель всегда показывает актуальную JSON-структуру архитектуры
- **Режимы работы** — «Черновик» (разрешены повисшие связи) и «Финал» (валидация)
- **Полиморфные классы** — REST, gRPC, PubSub эндпоинты; синхронные, асинхронные, потоковые связи

## Архитектурная модель

### Flat Aggregation

Спецификация использует плоскую структуру с корневыми массивами, элементы ссылаются друг на друга по уникальным `id`:

| Массив | Содержимое |
|---|---|
| `contracts[]` | Схемы данных: поля и их типы |
| `endpoints[]` | REST, gRPC, PubSub эндпоинты |
| `services[]` | Микросервисы с координатами на канвасе |
| `connections[]` | Сценарии взаимодействия между сервисами |

### Классы эндпоинтов

| `$class` | Описание | Ключевые свойства |
|---|---|---|
| `RestEndpoint` | HTTP REST API | `path`, `method`, `response.status`, `response.body_ref` |
| `GrpcEndpoint` | gRPC RPC | `package`, `service_name`, `rpc_method`, `response.body_ref` |
| `PubSubChannel` | Канал брокера сообщений | `topic_name`, `broker_type` (kafka/rabbitmq), `message_schema_ref` |

### Классы взаимодействий

| `$class` | Описание | Ключевые свойства |
|---|---|---|
| `SyncRequestResponse` | Синхронный запрос-ответ | `timeout_ms`, `retry_policy` |
| `AsyncFireAndForget` | Асинхронная публикация | `delivery_guarantee` |
| `StreamingInteraction` | Потоковое соединение | — |

### Режимы контракта

- **`strict`** — связь использует контракт эндпоинта по умолчанию
- **`override`** — связь перегружает ответ (например, legacy-флаги)

### Режимы работы

- **Черновик** — разрешены связи без привязки к целевому эндпоинту («повисшие нити»)
- **Финал** — все связи должны быть замкнуты, иначе статус показывает ошибку

## Как запустить

1. Откройте `index.html` в любом современном браузере
2. Никакой сборки или установки зависимостей не требуется

## Взаимодействие

| Действие | Результат |
|---|---|
| Клик по сервису/эндпоинту/связи | Выделение и открытие инспектора |
| Перетаскивание за шапку сервиса | Перемещение по канвасу |
| Перетаскивание от `●` на правом краю шапки | Создание новой связи |
| Перетаскивание от оранжевого коннектора на конце нити | Переподключение связи к другому эндпоинту |
| Клик по элементу в левой панели | Выделение на канвасе |
| Кнопки «Черновик» / «Финал» | Переключение режима валидации |

## Пример данных

В приложении загружена демо-архитектура **OnlineShop**:

```
API Gateway → Auth Service       (REST: POST /v1/auth/login)
API Gateway → Catalog Service    (REST: GET  /v1/products)
API Gateway → Order Service      (REST: POST /v1/orders)
Order Service → Payment Service  (gRPC: PaymentService.Charge)
Order Service → Notification     (Kafka: orders.v1.created)
```

## Live JSON

Правая панель отображает текущее состояние архитектуры в формате `architecture.mcs.json`. Структура включает `mcs_version`, `system_name`, `metadata`, `contracts`, `endpoints`, `services`, `connections`.

## История

Проект вырос из серии архитектурных дискуссий о стандарте описания связей между микросервисами (см. `DOCS.md`). Версии стандарта эволюционировали от YAML-концептов v1.0–v1.4 к JSON-модели v3.0 с полиморфными классами и плоской агрегацией.
